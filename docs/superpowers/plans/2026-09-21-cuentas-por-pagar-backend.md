# Cuentas por Pagar — Backend Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the backend half of Cuentas por Pagar — `cuenta_por_pagar` and `transaccion_pago_compra` tables, their services/controllers, and the hooks that make every `Compra` and every `Gasto` automatically generate a `CuentaPorPagar`. This plan is backend-only and API-testable on its own (via the new REST endpoints); the frontend screens are a separate follow-up plan.

**Architecture:** New `CuentaPorPagar`/`TransaccionPagoCompra` entities live in the existing `cl.slimerp.tesoreria` package, next to `CuentaPorCobrar`/`TransaccionPago` — same domain, mirrored pattern (`CuentaPorPagarService.crearParaCompra(Compra, String)`/`crearParaGasto(Gasto, String)` mirror `CuentaPorCobrarService.crearParaVenta(Venta)`; `TransaccionPagoCompraService` mirrors `TransaccionPagoService` almost line-for-line, including reusing the existing `EstadoTransaccion` and `MedioPago` enums and the existing `TransaccionPagoRequest`/`AnularRequest` records). `CompraService.crear()` and `GastoService.crear()`/`crearDesdeRecurrente()` (from the already-merged Módulo de Gastos) each get one line added at the end to call `CuentaPorPagarService`.

**Tech Stack:** Spring Boot 3 / Java, JPA + Flyway on PostgreSQL, Spring Data `Specification` + `Pageable` for the payments search.

**Spec:** `docs/superpowers/specs/2026-09-21-cuentas-por-pagar-design.md` — sections "1b. Backend — modelo de datos: cl.slimerp.tesoreria" and the `cl.slimerp.tesoreria` half of "2. Backend — servicios y endpoints". This plan refines two details the spec left implicit, both driven by the spec's own stated filter requirements:
- `cuenta_por_pagar` gains `proveedor_id` and `categoria_gasto_id` columns, denormalized from the origin (nullable, only one set per row's origin) — the spec's own text requires filtering by `proveedorId` (origin=Compra) and `categoriaGastoId` (origin=Gasto), which is impossible without either a join on every list query or these columns. Mirrors how `CuentaPorCobrar` already denormalizes `clienteId` from `Venta`.
- `TransaccionPagoCompraService.buscar()` uses `Specification` + `Pageable` (true DB-level pagination) instead of `TransaccionPagoService`'s in-memory pagination — that in-memory approach exists there only because searching by client name/RUT has no JPA-mapped field to query against; `transaccion_pago_compra` has no equivalent free-text search requirement in the spec, so the simpler, faster DB-level approach applies directly (same technique `GastoService.buscar()` already uses).

This plan also closes two findings the Módulo de Gastos final review parked for "when Cuentas por Pagar touches this code" (see that plan's ledger): `GastoService.crearDesdeRecurrente` will now validate its category (previously it didn't, unlike `crear()`) — required here anyway, since `crearParaGasto` needs the category's name — and `GastoRecurrenteGeneratorJob.generarParaTenant`'s loop gets a per-recurring-template `try/catch` (it currently only has a per-tenant one), so one template hitting the now-thrown validation error doesn't block its siblings for the same tenant.

## Global Constraints

- `id` is always `BIGINT GENERATED BY DEFAULT AS IDENTITY`, generated by the database — never sent by the frontend, never assigned in code.
- Every table has `tenant_id BIGINT NOT NULL REFERENCES tenant(id)`; every query filters by `TenantContext.getTenantId()`.
- No new permissions: every new endpoint reuses `TESORERIA_VER` / `TESORERIA_EDITAR` / `TESORERIA_ANULAR`, exactly like `CuentaPorCobrarController`/`TransaccionPagoController` already do.
- `cuenta_por_pagar.compra_id`/`gasto_id`: exactly one is set per row, enforced by a `CHECK` constraint — never both, never neither.
- No `CuentaPorPagar` row is ever created twice for the same `Compra` or the same `Gasto` — every creation path is idempotent (mirrors `CuentaPorCobrarService.crearParaVenta`'s idempotency check).
- No git commands that mutate the repository (`add`, `commit`, `push`, `merge`, `reset`, branch creation, etc.) may run as part of executing this plan — not even the "Commit" steps below — unless the user explicitly asks for it in the moment. Treat every "Commit" step as the exact `git add`/`git commit` text to show the user, not a command to run automatically. Read-only git commands (`status`, `diff`, `log`, `show`) are fine.
- Backend has no local Java/Maven — verify compilation and run tests via the `maven:3.9-eclipse-temurin-21` Docker image, from the repo root (not from inside `backend/`):
  ```bash
  docker run --rm -v "$(pwd)/backend:/app" -w /app -v slime_erp_maven_repo:/root/.m2 \
    maven:3.9-eclipse-temurin-21 mvn -q test -Dtest=<ClassName>
  ```
- Out of scope for this plan: the frontend Cuentas por Pagar screens (a separate follow-up plan), and the Flujo de Caja sync of confirmed payments (a further follow-up plan that depends on this one).

```sql
-- Cuentas por Pagar: deuda generada por documentos de compra y por gastos
-- (puntuales o recurrentes), con pagos parciales registrados en
-- transaccion_pago_compra. Origen exclusivo: compra_id o gasto_id, nunca
-- ambos (ver CHECK). proveedor_id/categoria_gasto_id se denormalizan desde
-- el origen para poder filtrar/agrupar sin join, igual que cuenta_por_cobrar
-- denormaliza cliente_id desde venta.

CREATE TABLE cuenta_por_pagar (
    id                  BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    tenant_id           BIGINT       NOT NULL REFERENCES tenant(id),
    compra_id           BIGINT REFERENCES compra(id),
    gasto_id            BIGINT REFERENCES gasto(id),
    proveedor_id        BIGINT REFERENCES proveedor(id),
    categoria_gasto_id  BIGINT REFERENCES categoria_gasto(id),
    descripcion         VARCHAR(255) NOT NULL,
    fecha_generacion    TIMESTAMP    NOT NULL DEFAULT now(),
    monto_total         NUMERIC(14,2) NOT NULL,
    monto_pagado        NUMERIC(14,2) NOT NULL DEFAULT 0,
    saldo_pendiente     NUMERIC(14,2) NOT NULL,
    estado              VARCHAR(20)  NOT NULL DEFAULT 'DEUDA',
    fecha_ultimo_pago   TIMESTAMP,
    observaciones       VARCHAR(500),
    usuario_anulo_id    BIGINT REFERENCES usuario(id),
    fecha_anulacion     TIMESTAMP,
    motivo_anulacion    VARCHAR(500),
    CONSTRAINT ck_cxp_un_origen CHECK (
        (compra_id IS NOT NULL AND gasto_id IS NULL) OR
        (compra_id IS NULL AND gasto_id IS NOT NULL)
    ),
    CONSTRAINT ck_cxp_saldo_no_negativo CHECK (saldo_pendiente >= 0),
    CONSTRAINT ck_cxp_pagado_no_excede CHECK (monto_pagado <= monto_total)
);
CREATE UNIQUE INDEX uq_cxp_compra ON cuenta_por_pagar(tenant_id, compra_id) WHERE compra_id IS NOT NULL;
CREATE UNIQUE INDEX uq_cxp_gasto ON cuenta_por_pagar(tenant_id, gasto_id) WHERE gasto_id IS NOT NULL;
CREATE INDEX idx_cxp_tenant_estado ON cuenta_por_pagar(tenant_id, estado);
CREATE INDEX idx_cxp_proveedor ON cuenta_por_pagar(tenant_id, proveedor_id);
CREATE INDEX idx_cxp_categoria_gasto ON cuenta_por_pagar(tenant_id, categoria_gasto_id);

CREATE TABLE transaccion_pago_compra (
    id                              BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    tenant_id                       BIGINT       NOT NULL REFERENCES tenant(id),
    cuenta_por_pagar_id             BIGINT       NOT NULL REFERENCES cuenta_por_pagar(id),
    compra_id                       BIGINT,
    gasto_id                        BIGINT,
    fecha                           TIMESTAMP    NOT NULL DEFAULT now(),
    monto                           NUMERIC(14,2) NOT NULL,
    medio_pago                      VARCHAR(20)  NOT NULL,
    estado                          VARCHAR(20)  NOT NULL DEFAULT 'CONFIRMADA',
    usuario_id                      BIGINT REFERENCES usuario(id),
    observaciones                   VARCHAR(500),
    transferencia_banco_origen      VARCHAR(100),
    transferencia_banco_destino     VARCHAR(100),
    transferencia_numero_operacion  VARCHAR(100),
    transferencia_fecha             DATE,
    tarjeta_entidad                 VARCHAR(100),
    tarjeta_tipo                    VARCHAR(50),
    tarjeta_numero_operacion        VARCHAR(100),
    tarjeta_fecha                   DATE,
    cheque_banco                    VARCHAR(100),
    cheque_numero                   VARCHAR(50),
    cheque_fecha_emision            DATE,
    cheque_fecha_pago               DATE,
    usuario_anulo_id                BIGINT REFERENCES usuario(id),
    fecha_anulacion                 TIMESTAMP,
    motivo_anulacion                VARCHAR(500),
    CONSTRAINT ck_pago_compra_monto_positivo CHECK (monto > 0)
);
CREATE INDEX idx_pago_compra_tenant ON transaccion_pago_compra(tenant_id);
CREATE INDEX idx_pago_compra_cuenta ON transaccion_pago_compra(cuenta_por_pagar_id);
CREATE INDEX idx_pago_compra_fecha ON transaccion_pago_compra(tenant_id, fecha);
```

```java
package cl.slimerp.tesoreria;

import cl.slimerp.compras.Compra;
import cl.slimerp.config.TenantContext;
import cl.slimerp.gastos.Gasto;
import org.junit.jupiter.api.AfterEach;
import org.junit.jupiter.api.BeforeEach;
import org.junit.jupiter.api.Test;

import java.math.BigDecimal;
import java.time.LocalDate;
import java.util.List;

import static org.junit.jupiter.api.Assertions.*;
import static org.mockito.ArgumentMatchers.any;
import static org.mockito.Mockito.*;

class CuentaPorPagarServiceTest {

    private CuentaPorPagarRepository repository;
    private CuentaPorPagarService service;

    private final Long tenantId = 1L;

    @BeforeEach
    void setUp() {
        repository = mock(CuentaPorPagarRepository.class);
        service = new CuentaPorPagarService(repository);
        TenantContext.setTenantId(tenantId);

        when(repository.save(any(CuentaPorPagar.class))).thenAnswer(inv -> {
            CuentaPorPagar c = inv.getArgument(0);
            if (c.getId() == null) c.setId(100L);
            return c;
        });
    }

    @AfterEach
    void tearDown() {
        TenantContext.clear();
    }

    private Compra compra(Long id, BigDecimal total, Long proveedorId) {
        return Compra.builder().id(id).tenantId(tenantId).proveedorId(proveedorId).bodegaId(1L)
                .total(total).build();
    }

    private Gasto gasto(Long id, BigDecimal monto, Long categoriaGastoId) {
        return Gasto.builder().id(id).tenantId(tenantId).categoriaGastoId(categoriaGastoId)
                .monto(monto).descripcion("Arriendo oficina").fecha(LocalDate.now()).build();
    }

    @Test
    void crearParaCompraGeneraLaCuentaConElSaldoIgualAlTotal() {
        when(repository.findByTenantIdAndCompraId(tenantId, 1L)).thenReturn(Optional.empty());

        service.crearParaCompra(compra(1L, new BigDecimal("50000"), 7L), "Proveedor Uno");

        verify(repository).save(argThat(c ->
                c.getCompraId().equals(1L) && c.getGastoId() == null
                        && c.getProveedorId().equals(7L)
                        && c.getDescripcion().equals("Compra C-1 — Proveedor Uno")
                        && c.getMontoTotal().compareTo(new BigDecimal("50000")) == 0

                        && c.getEstado() == EstadoCuentaPorPagar.DEUDA));

        when(repository.findByTenantIdAndCompraId(tenantId, 1L)).thenReturn(Optional.of(existente));

        service.crearParaCompra(compra(1L, new BigDecimal("50000"), 7L), "Proveedor Uno");

        verify(repository, never()).save(any());
```
```java
    }

    // Se invoca desde CompraService al confirmar una compra. Idempotente: si
    // ya existe una cuenta para esa compra, no crea otra.
    @Transactional
    public void crearParaCompra(Compra compra, String nombreProveedor) {
        Long tenantId = compra.getTenantId();
        if (cuentaPorPagarRepository.findByTenantIdAndCompraId(tenantId, compra.getId()).isPresent()) {
            return;
        }

        cuentaPorPagarRepository.save(CuentaPorPagar.builder()
                .tenantId(tenantId)
                .compraId(compra.getId())
                .proveedorId(compra.getProveedorId())
                .descripcion("Compra C-" + compra.getId() + " — " + nombreProveedor)
                .montoTotal(compra.getTotal())
                .montoPagado(BigDecimal.ZERO)
                .saldoPendiente(compra.getTotal())
                .estado(EstadoCuentaPorPagar.DEUDA)
                .build());
    }

    // Se invoca desde GastoService al crear un gasto puntual o generado desde
    // una plantilla recurrente. Idempotente: si ya existe una cuenta para ese
    // gasto, no crea otra.
    @Transactional
    public void crearParaGasto(Gasto gasto, String nombreCategoria) {
        Long tenantId = gasto.getTenantId();
        if (cuentaPorPagarRepository.findByTenantIdAndGastoId(tenantId, gasto.getId()).isPresent()) {
            return;
        }

        cuentaPorPagarRepository.save(CuentaPorPagar.builder()
                .tenantId(tenantId)
                .gastoId(gasto.getId())
                .categoriaGastoId(gasto.getCategoriaGastoId())
                .descripcion(nombreCategoria + ": " + gasto.getDescripcion())
                .montoTotal(gasto.getMonto())
                .montoPagado(BigDecimal.ZERO)
                .saldoPendiente(gasto.getMonto())
                .estado(EstadoCuentaPorPagar.DEUDA)
                .build());
    }

    public List<CuentaPorPagar> listar(Long proveedorId, Long categoriaGastoId, EstadoCuentaPorPagar estado) {
        Long tenantId = TenantContext.getTenantId();
        if (proveedorId != null) {
            return cuentaPorPagarRepository.findByTenantIdAndProveedorIdOrderByFechaGeneracionDesc(tenantId, proveedorId);
        }
        if (categoriaGastoId != null) {
            return cuentaPorPagarRepository.findByTenantIdAndCategoriaGastoIdOrderByFechaGeneracionDesc(tenantId, categoriaGastoId);
        }
        if (estado != null) {
            return cuentaPorPagarRepository.findByTenantIdAndEstadoOrderByFechaGeneracionDesc(tenantId, estado);
        }
        return cuentaPorPagarRepository.findByTenantIdOrderByFechaGeneracionDesc(tenantId);
    }

    public CuentaPorPagar obtener(Long id) {
        return cuentaPorPagarRepository.findByIdAndTenantId(id, TenantContext.getTenantId())
                .orElseThrow(() -> new IllegalArgumentException("Cuenta por pagar no encontrada: " + id));
    }

    public ResumenCuentasPorPagar resumen() {
        List<CuentaPorPagar> cuentas = cuentaPorPagarRepository.findByTenantIdOrderByFechaGeneracionDesc(TenantContext.getTenantId());

        BigDecimal totalPorPagar = BigDecimal.ZERO;
        BigDecimal totalPagado = BigDecimal.ZERO;
        BigDecimal saldoPendiente = BigDecimal.ZERO;
        long enDeuda = 0;
        long parciales = 0;
        long pagadas = 0;

        for (CuentaPorPagar cuenta : cuentas) {
            if (cuenta.getEstado() == EstadoCuentaPorPagar.ANULADO) continue;
            totalPorPagar = totalPorPagar.add(cuenta.getMontoTotal());
            totalPagado = totalPagado.add(cuenta.getMontoPagado());
            saldoPendiente = saldoPendiente.add(cuenta.getSaldoPendiente());
            switch (cuenta.getEstado()) {
                case DEUDA -> enDeuda++;
                case PARCIAL -> parciales++;
                case PAGADO -> pagadas++;
                default -> { }
            }
        }

        return new ResumenCuentasPorPagar(totalPorPagar, totalPagado, saldoPendiente, enDeuda, parciales, pagadas);
    }

    @Transactional
    public CuentaPorPagar anular(Long id, String motivo, Long usuarioId) {
        CuentaPorPagar cuenta = obtener(id);

        if (cuenta.getEstado() == EstadoCuentaPorPagar.ANULADO) {
            throw new IllegalArgumentException("La cuenta ya está anulada");
        }
        if (cuenta.getEstado() == EstadoCuentaPorPagar.PAGADO) {
            throw new IllegalArgumentException("No se puede anular una cuenta ya pagada");
        }

        cuenta.setEstado(EstadoCuentaPorPagar.ANULADO);
        cuenta.setUsuarioAnuloId(usuarioId);
        cuenta.setFechaAnulacion(LocalDateTime.now());
        cuenta.setMotivoAnulacion(motivo);
        return cuentaPorPagarRepository.save(cuenta);
    }
```

```java
import cl.slimerp.common.PaginaResponse;
import cl.slimerp.config.TenantContext;
```

```java
import java.time.LocalDateTime;
import java.util.List;

@Service
public class TransaccionPagoCompraService {

    private final TransaccionPagoCompraRepository transaccionPagoCompraRepository;
    private final CuentaPorPagarRepository cuentaPorPagarRepository;

    public TransaccionPagoCompraService(TransaccionPagoCompraRepository transaccionPagoCompraRepository,
                                         CuentaPorPagarRepository cuentaPorPagarRepository) {
        this.transaccionPagoCompraRepository = transaccionPagoCompraRepository;
        this.cuentaPorPagarRepository = cuentaPorPagarRepository;
    }

    @Transactional
    public TransaccionPagoCompra registrarPago(Long cuentaId, TransaccionPagoRequest request, Long usuarioId) {
        Long tenantId = TenantContext.getTenantId();
        CuentaPorPagar cuenta = cuentaPorPagarRepository.findByIdAndTenantId(cuentaId, tenantId)
                .orElseThrow(() -> new IllegalArgumentException("Cuenta por pagar no encontrada: " + cuentaId));

        if (cuenta.getEstado() != EstadoCuentaPorPagar.DEUDA && cuenta.getEstado() != EstadoCuentaPorPagar.PARCIAL) {
            throw new IllegalArgumentException("No se puede registrar un pago sobre una cuenta " + cuenta.getEstado());
        }
        if (request.monto().compareTo(cuenta.getSaldoPendiente()) > 0) {
            throw new IllegalArgumentException(
                    "El monto excede el saldo pendiente (" + cuenta.getSaldoPendiente() + ")");
        }
        validarDatosMedioPago(request);

        TransaccionPagoCompra pago = TransaccionPagoCompra.builder()
                .tenantId(tenantId)
                .cuentaPorPagarId(cuenta.getId())
                .compraId(cuenta.getCompraId())
                .gastoId(cuenta.getGastoId())
                .monto(request.monto())
                .medioPago(request.medioPago())
                .observaciones(request.observaciones())
                .transferenciaBancoOrigen(request.transferenciaBancoOrigen())
                .transferenciaBancoDestino(request.transferenciaBancoDestino())
                .transferenciaNumeroOperacion(request.transferenciaNumeroOperacion())
                .transferenciaFecha(request.transferenciaFecha())
                .tarjetaEntidad(request.tarjetaEntidad())
                .tarjetaTipo(request.tarjetaTipo())
                .tarjetaNumeroOperacion(request.tarjetaNumeroOperacion())
                .tarjetaFecha(request.tarjetaFecha())
                .chequeBanco(request.chequeBanco())
                .chequeNumero(request.chequeNumero())
                .chequeFechaEmision(request.chequeFechaEmision())
                .chequeFechaPago(request.chequeFechaPago())
                .usuarioId(usuarioId)
                .build();
        pago = transaccionPagoCompraRepository.save(pago);

        cuenta.setMontoPagado(cuenta.getMontoPagado().add(request.monto()));
        cuenta.setSaldoPendiente(cuenta.getMontoTotal().subtract(cuenta.getMontoPagado()));
        cuenta.setEstado(cuenta.getSaldoPendiente().signum() == 0
                ? EstadoCuentaPorPagar.PAGADO
                : EstadoCuentaPorPagar.PARCIAL);
        cuenta.setFechaUltimoPago(pago.getFecha());
        cuentaPorPagarRepository.save(cuenta);

        return pago;
    }

    private void validarDatosMedioPago(TransaccionPagoRequest request) {
        switch (request.medioPago()) {
            case TRANSFERENCIA -> {
                if (esVacio(request.transferenciaBancoOrigen()) || esVacio(request.transferenciaBancoDestino())) {
                    throw new IllegalArgumentException("Debes indicar el banco de origen y destino de la transferencia");
                }
            }
            case TARJETA -> {
                if (esVacio(request.tarjetaEntidad())) {
                    throw new IllegalArgumentException("Debes indicar la entidad de la tarjeta");
                }
            }
            case CHEQUE -> {
                if (esVacio(request.chequeBanco()) || esVacio(request.chequeNumero())) {
                    throw new IllegalArgumentException("Debes indicar el banco y número del cheque");
                }
            }
            case EFECTIVO -> {
                // Sin datos adicionales requeridos.
            }
        }
    }

    private boolean esVacio(String valor) {
        return valor == null || valor.isBlank();
    }

    public List<TransaccionPagoCompra> listarPorCuenta(Long cuentaId) {
        return transaccionPagoCompraRepository.findByTenantIdAndCuentaPorPagarIdOrderByFechaDesc(
                TenantContext.getTenantId(), cuentaId);
    }

    public PaginaResponse<TransaccionPagoCompra> buscar(EstadoTransaccion estado, MedioPago medioPago,
                                                          LocalDateTime fechaDesde, LocalDateTime fechaHasta,
                                                          int pagina, int tamano) {
        if (pagina < 0) throw new IllegalArgumentException("La página debe ser 0 o mayor");
        if (tamano < 1) throw new IllegalArgumentException("El tamaño de página debe ser mayor que 0");
        Long tenantId = TenantContext.getTenantId();

        Specification<TransaccionPagoCompra> spec = (root, query, cb) -> cb.equal(root.get("tenantId"), tenantId);
        if (estado != null) {
            spec = spec.and((root, query, cb) -> cb.equal(root.get("estado"), estado));
        }
        if (medioPago != null) {
            spec = spec.and((root, query, cb) -> cb.equal(root.get("medioPago"), medioPago));

                .findByTenantIdAndCuentaPorPagarIdAndEstado(tenantId, cuenta.getId(), EstadoTransaccion.CONFIRMADA)
                .stream()
                .map(TransaccionPagoCompra::getMonto)
                .reduce(BigDecimal.ZERO, BigDecimal::add);

        cuenta.setSaldoPendiente(cuenta.getMontoTotal().subtract(montoPagado));
        cuenta.setEstado(montoPagado.signum() == 0
                ? EstadoCuentaPorPagar.DEUDA
                : cuenta.getSaldoPendiente().signum() == 0 ? EstadoCuentaPorPagar.PAGADO : EstadoCuentaPorPagar.PARCIAL);
        cuentaPorPagarRepository.save(cuenta);
```

## What this plan deliberately does not do

- No `Gasto` edit/delete → `CuentaPorPagar` sync — `GastoService.actualizar()`/`eliminar()` (pre-existing, from the Módulo de Gastos plan) do not update or annul the `CuentaPorPagar` they generated. Editing an expense's amount after this branch ships leaves the payable's `montoTotal` stale; deleting an expense leaves an orphan `DEUDA` payable. Closing this needs a product decision this plan's final review flagged as out of scope for a mechanical fix (what happens to payment history on an already-partially-paid expense that gets edited or deleted?) — design it explicitly before or alongside the frontend follow-up plan, which is the first point this gap becomes reachable by a user.

- No frontend — the Cuentas por Pagar screens (`features/cuentas-por-pagar/`), their services, routes, and nav entries are a separate follow-up plan that consumes the endpoints this plan builds.
- No Flujo de Caja sync of confirmed payments — a further follow-up plan, depending on the frontend plan existing first (per the spec's sync design, which needs `TransaccionPagoCompraService.buscar` — already built here — plus new frontend sync-service code).
- No `cuentaPorPagarDescripcion` joined field on the `/api/tesoreria/pagos-compra` response — the frontend historial screen (follow-up plan) resolves a payment's description by cross-referencing the already-loaded Cuentas por Pagar list client-side, the same way `GastosComponent.nombreCategoriaDe()` already does for categories. If the eventual Flujo de Caja sync plan needs the description embedded directly in the payments response (to avoid the frontend needing both lists loaded), that plan can add a thin response DTO then, at that point where it's driven by an actual consumer.
