# NC-002 — Modelo de datos

## Objetivo

Definir el esquema y las entidades JPA de la Nota de Crédito, y preparar
`movimiento_inventario` para los tipos de movimiento nuevos.

## Convenciones del repositorio (obligatorias)

- `id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY` en toda tabla.
  El `id` lo genera la base de datos; nunca se envía desde el frontend ni se calcula en la
  lógica de negocio.
- En JPA: `@Id @GeneratedValue(strategy = GenerationType.IDENTITY)`.
- `tenant_id BIGINT NOT NULL REFERENCES tenant(id)` en toda tabla de negocio, y primero en
  cualquier índice compuesto.
- `ON DELETE CASCADE` en las tablas hijas.
- `CHECK` de no-negatividad en cantidades y montos.
- Comentarios en español explicando el *porqué* de cada tabla, al estilo de
  `V36__notas_venta.sql`.
- Lombok `@Getter @Setter @NoArgsConstructor @AllArgsConstructor @Builder` + `@Builder.Default`.
- Relaciones "duras" solo con las líneas propias; cliente, usuario, bodega y venta se
  guardan como `Long xxxId` y se resuelven en el Service.

## Migración: `backend/src/main/resources/db/migration/V37__notas_credito.sql`

`V36` es la migración más alta actual, así que esta es `V37`.

### 1. `nota_credito_folio_contador`

Correlativo por tenant, idéntico a `nota_venta_folio_contador`:

```sql
CREATE TABLE nota_credito_folio_contador (
    id           BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    tenant_id    BIGINT  NOT NULL REFERENCES tenant(id),
    ultimo_folio INTEGER NOT NULL DEFAULT 0,
    CONSTRAINT uq_nota_credito_folio_tenant UNIQUE (tenant_id)
);
```

### 4. `nota_credito_evento`

Historial append-only, copia de `nota_venta_evento`: `id`, `tenant_id`,
`nota_credito_id` (CASCADE), `usuario_id` (nullable), `accion VARCHAR(30) NOT NULL`,
`estado_anterior VARCHAR(20)`, `estado_nuevo VARCHAR(20)`, `detalle VARCHAR(500)`,
`fecha TIMESTAMP NOT NULL DEFAULT now()`.
Índice `(nota_credito_id, fecha)`.

### 6. Ensanchamiento de `movimiento_inventario.tipo`

`TipoMovimiento` gana `ENTRADA_NOTA_CREDITO` (20 caracteres) y
`SALIDA_ANULA_NOTA_CREDITO` (25). La columna actual es `VARCHAR(20)` y no alcanza:

```sql
ALTER TABLE movimiento_inventario        ALTER COLUMN tipo TYPE VARCHAR(30);
ALTER TABLE movimiento_inventario_header ALTER COLUMN tipo TYPE VARCHAR(30);
```

En la misma tarea, actualizar `@Column(nullable = false, length = 30)` en
`inventario/MovimientoInventario.java` y `inventario/MovimientoInventarioHeader.java`.
Con `ddl-auto: validate`, si las longitudes no coinciden el backend no arranca.
