# ND-002 — Modelo de datos

## Objetivo

Definir el esquema y las entidades JPA de la Nota de Débito. La ND revierte una Nota de
Crédito `EMITIDA`, por lo que su esquema hereda de `V37__notas_credito.sql` y añade los
tipos de movimiento de inventario para la reversión.

## Convenciones del repositorio (obligatorias)

- `id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY` en toda tabla. El `id` lo
  genera la base de datos; nunca se envía desde el frontend ni se calcula en la lógica de
  negocio.
- En JPA: `@Id @GeneratedValue(strategy = GenerationType.IDENTITY)`.
- `tenant_id BIGINT NOT NULL REFERENCES tenant(id)` en toda tabla de negocio, y primero
  en cualquier índice compuesto.
- `ON DELETE CASCADE` en las tablas hijas.
- `CHECK` de no-negatividad en cantidades y montos.
- Comentarios en español explicando el *porqué* de cada tabla, al estilo de
  `V37__notas_credito.sql`.
- Lombok `@Getter @Setter @NoArgsConstructor @AllArgsConstructor @Builder` +
  `@Builder.Default`.
- Relaciones "duras" solo con las líneas propias; cliente, usuario, bodega y la NC se
  guardan como `Long xxxId` y se resuelven en el Service. La excepción es `nota_credito_id`,
  que sí es FK a `nota_credito(id)` (documento asociado).

## Migración: `backend/src/main/resources/db/migration/V39__notas_debito.sql`

`V38` es la migración más alta actual, así que esta es `V39`.

### 1. `nota_debito_folio_contador`

Correlativo por tenant, idéntico a `nota_credito_folio_contador`:

```sql
CREATE TABLE nota_debito_folio_contador (
    id           BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    tenant_id    BIGINT  NOT NULL REFERENCES tenant(id),
    ultimo_folio INTEGER NOT NULL DEFAULT 0,
    CONSTRAINT uq_nota_debito_folio_tenant UNIQUE (tenant_id)
);
```


### 4. `nota_debito_evento`

Historial append-only, copia de `nota_credito_evento`: `id`, `tenant_id`,
`nota_debito_id` (CASCADE), `usuario_id` (nullable), `accion VARCHAR(30) NOT NULL`,
`estado_anterior VARCHAR(20)`, `estado_nuevo VARCHAR(20)`, `detalle VARCHAR(500)`,
`fecha TIMESTAMP NOT NULL DEFAULT now()`. Índice `(nota_debito_id, fecha)`.

### 6. Tipos de movimiento nuevos en `TipoMovimiento` (inventario)

La columna ya es `VARCHAR(30)` desde `V37`, así que **no** hay que ensanchar. Agregar al
enum `cl.slimerp.inventario.TipoMovimiento`:

- `SALIDA_NOTA_CREDITO` — salida al emitir la ND: revierte la `ENTRADA_NOTA_CREDITO`
  que la NC había generado.
- `ENTRADA_NOTA_DEBITO` — entrada al anular la ND: revierte la `SALIDA_NOTA_CREDITO`
  propia (restaura el stock que la ND había sacado).

La cabecera de inventario usa `SALIDA` / `ENTRADA` (mismo patrón que `NotaCreditoService`).
